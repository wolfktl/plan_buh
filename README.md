# Планировщик бухгалтера — налоговый календарь РФ 2026

Self-hosted веб-приложение для ведения сроков сдачи отчётности и уплаты налогов
в разрезе контрагентов. Налоговый календарь на 2026 год с автоматическим
переносом сроков на рабочий день, справочник контрагентов, отметки выполнения,
собственные задачи. Доступ защищён логином, паролем и двухфакторной
аутентификацией (TOTP).

## Возможности

- **Налоговый календарь 2026** — единые сроки ЕНС (отчётность до 25-го, уплата
  до 28-го), НДФЛ по двум периодам, квартальная и годовая отчётность, взносы ИП.
  Даты рассчитываются в коде с переносом на ближайший рабочий день
  (п. 7 ст. 6.1 НК РФ) по производственному календарю 2026
  (Постановление Правительства РФ № 1466 от 24.09.2025).
- **Справочник контрагентов** — организации и ИП с указанием формы, системы
  налогообложения (ОСНО/УСН), наличия сотрудников, ИНН/КПП.
- **Фильтр по контрагенту** — для каждого контрагента свой набор применимых
  дедлайнов и свои отметки о выполнении. Неприменимые к режиму события
  скрываются (можно показать).
- **Отметки выполнения и свои задачи** — хранятся на сервере, привязаны
  к контрагенту.
- **Календарь-сетка и заметки** — общий просмотр по месяцам (доступен без
  выбора контрагента): налоговые сроки и личные заметки в одной сетке. Заметки
  с заголовком, текстом, цветовой меткой и отметкой выполнения (в духе
  tweek.so); клик по дню — добавить заметку, клик по сроку — детали. Сбоку —
  столбец ближайших налоговых сроков на 6 недель вперёд.
- **Оповещения о напоминаниях** — на каждой заметке задаётся время и каналы:
  Telegram, Email, браузерные push (Web Push). Рассылает отдельный сервис
  `worker`. SMTP и токен Telegram-бота настраивает администратор в разделе
  «Настройки → Оповещения — сервер»; личные каналы (email, привязка Telegram,
  push) пользователь подключает там же.
- **Аутентификация** — пароль (bcrypt) + опциональная 2FA (TOTP, совместимо
  с Google Authenticator, Яндекс.Ключ, 2FAS и др.), которую пользователь
  включает и отключает в разделе «Настройки». Сессии в httpOnly-cookie (JWT).
- **Пользователи и роли** — многопользовательский режим с ролями `admin`
  и `user`. Первый зарегистрированный — администратор. В разделе «Пользователи»
  (виден только администратору) можно заводить учётные записи, менять роли,
  сбрасывать пароль и 2FA, отключать и удалять пользователей. У каждого
  пользователя свой изолированный список контрагентов. Нельзя снять права или
  удалить последнего администратора.

## Технологии

FastAPI · SQLAlchemy · PostgreSQL · bcrypt · PyJWT · pyotp · pywebpush · Docker.
Отдельный воркер-сервис для рассылки напоминаний. Фронтенд — статический
HTML/CSS/JS без внешних CDN (service worker для push). Для локального запуска
без Docker поддерживается SQLite.

## Быстрый старт

```bash
git clone https://github.com/wolfktl/plan_buh.git
cd plan_buh

cp .env.example .env
# сгенерируйте секреты и впишите в .env:
sed -i "s|^SECRET_KEY=.*|SECRET_KEY=$(openssl rand -base64 48)|" .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -base64 24)|" .env

docker compose up -d --build
```

Поднимаются два сервиса: `db` (PostgreSQL) и `app`; приложение ждёт готовности
БД по healthcheck.

Откройте `http://<сервер>:8080` (порт настраивается через `APP_PORT`).
При первом входе создайте учётную запись — она становится **администратором**.
Остальных пользователей администратор заводит в разделе «Пользователи» (👥).
Двухфакторную аутентификацию каждый включает сам в разделе «Настройки» (⚙️):
отсканируйте QR-код в приложении-аутентификаторе; там же её можно отключить.

## Конфигурация (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `SECRET_KEY` | Ключ подписи сессий (обязателен в проде) | временный |
| `APP_PORT` | Внешний порт | `8080` |
| `TZ` | Часовой пояс (время напоминаний) | `Europe/Moscow` |
| `COOKIE_SECURE` | Cookie только по HTTPS | `false` |
| `COOKIE_SAMESITE` | Политика SameSite | `lax` |
| `TOTP_ISSUER` | Имя в приложении-аутентификаторе | `ПланБух` |
| `SESSION_TTL_MIN` | Срок жизни сессии, мин | `720` |
| `PREAUTH_TTL_MIN` | Время на ввод кода 2FA, мин | `5` |
| `POSTGRES_USER` | Пользователь БД | `planbuh` |
| `POSTGRES_PASSWORD` | Пароль БД (обязателен) | — |
| `POSTGRES_DB` | Имя БД | `plan_buh` |
| `DATABASE_URL` | Полный URL БД (переопределяет `POSTGRES_*`) | — |
| `DB_PATH` | Файл SQLite (только запуск без Docker) | `/data/plan_buh.db` |

Выбор БД: задан `DATABASE_URL` → используется он; иначе заданы `POSTGRES_*`
→ PostgreSQL; иначе SQLite по `DB_PATH`.

## Данные и бэкап

Данные PostgreSQL лежат в именованном volume `pgdata`.

```bash
# бэкап
docker compose exec db pg_dump -U planbuh plan_buh > plan_buh-$(date +%F).sql

# восстановление
cat plan_buh-YYYY-MM-DD.sql | docker compose exec -T db psql -U planbuh plan_buh
```

## Эксплуатация за reverse-proxy

Для продакшена поставьте приложение за nginx/traefik с TLS и включите
`COOKIE_SECURE=true`. Пример проксирования nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

## Запуск без Docker (разработка)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# без POSTGRES_* приложение возьмёт локальный SQLite
export SECRET_KEY=dev-secret DB_PATH=./plan_buh.db
uvicorn app.main:app --reload --port 8000
```

API-документация (Swagger): `/api/docs`.

## Оповещения

Напоминания настраиваются на каждой личной заметке (дата/время + каналы).
Рассылку ведёт отдельный сервис `worker`.

Подключение каналов:

1. **Администратор** в «Настройки → Оповещения — сервер» вводит параметры SMTP
   и токен Telegram-бота (от `@BotFather`). Секреты хранятся в БД и не
   отображаются обратно.
2. **Email** — каждый пользователь указывает свой адрес в «Мои каналы».
3. **Telegram** — пользователь нажимает «Привязать», переходит по ссылке к боту
   и нажимает Start; воркер привязывает чат к аккаунту.
4. **Браузерные push** — кнопка «Включить на этом устройстве» (VAPID-ключи
   генерируются автоматически при первом запуске).

Кнопка «Отправить тестовое уведомление» проверяет настроенные каналы.

Часовой пояс для времени напоминаний задаётся переменной `TZ`.

## Оговорка

Инструмент вспомогательный. Состав и сроки отчётности зависят от режима,
наличия сотрудников и вида деятельности, а законодательство меняется. Перед
сдачей сверяйтесь с официальным календарём ФНС и своей учётной программой.

## Источники по срокам

Производственный календарь 2026 (Постановление Правительства РФ № 1466
от 24.09.2025), календарь бухгалтера 2026 (ФНС, профильные бухгалтерские
издания), правила ЕНС/ЕНП и уведомлений по НДФЛ (НК РФ).
